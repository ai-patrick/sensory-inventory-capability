Building a Sensor Inventory App with RecyclerView & SensorManager

An Android (Java) walkthrough: discovering device sensors, displaying detailed metadata in a RecyclerView, and comparing sensors for MavunoLink agricultural tracking use cases.

👤 Patrick Kilonzo Mbithi🆔 SCT211-0036/2024🎓 BSc Computer Science👨‍🏫 Dr. Lawrence Nderu

1 · Lab Objective

The goal of this lab is to build an Android application that enumerates all available hardware sensors on a device, presents their detailed specifications in an expandable RecyclerView, and provides a comparative analysis focused on motion tracking sensors relevant to the MavunoLink agricultural platform. By the end of this lab the app can:

📷Discover sensorsUse SensorManager.getSensorList(TYPE_ALL) to enumerate every hardware sensor.
📅Display metadataShow vendor, range, resolution, power, min/max delay, FIFO capacity, reporting mode, and wake-up capability.
✅Expandable cardsRecyclerView items toggle between summary and full detail view on tap.
💬Device profilingDetect emulator vs physical device; show model, Android version, build fingerprint.
📈MavunoLink comparisonAnalyze accelerometer vs gyroscope for 6-DoF motion tracking in agricultural contexts.
ComponentPurpose in this app
SensorManagerSystem service to query sensor hardware; getSensorList(TYPE_ALL) returns all sensors
RecyclerView + LinearLayoutManagerEfficiently renders scrollable list of sensor cards with view recycling
CardViewMaterial card containers for device info, sensor inventory, and comparison sections
Sensor classMetadata holder: type, vendor, range, resolution, power, delay, FIFO, reporting mode, wake-up
Build classDevice fingerprinting: MODEL, MANUFACTURER, VERSION, FINGERPRINT, HARDWARE for emulator detection
ConstraintLayout + ScrollViewRoot layout with scrollable content area for varying screen sizes

3 · User Interface Layouts

The main screen uses a ConstraintLayout root with a ScrollView → LinearLayout containing three CardView sections. Each sensor in the inventory is rendered via item_sensor.xml inflated by the RecyclerView adapter.

3.1 Root Layout (activity_main.xml)

The root ConstraintLayout applies window insets padding for edge-to-edge display. A ScrollView with fillViewport=true ensures content fills the screen even when sparse.

3.2 Device Info Card

First card displays device model, Android version, environment type (emulator/physical), and build fingerprint. Uses a vertical LinearLayout inside the CardView.

3.3 Sensor Inventory Card

Second card shows a sensor count badge and the RecyclerView. An empty state TextView is shown when no sensors are found.

💡 Tip. nestedScrollingEnabled="false" on the RecyclerView prevents scroll conflicts with the parent ScrollView. The RecyclerView height is wrap_content so it expands to show all items within the scrolling container.

3.4 Comparison Card

Third card presents the MavunoLink sensor comparison analysis as formatted text.

3.5 Sensor Item Layout (item_sensor.xml)

Each sensor is a CardView with a summary header (name + type) and an expandable details container. A divider and toggle label provide visual affordance.

4 · Activity Logic (MainActivity.java)

The Activity performs four primary tasks: initialize views → populate device info → populate sensor inventory → run MavunoLink comparison.

4.1 Imports and Field Declarations

Fields are declared at class level for view references, the SensorManager, and the RecyclerView adapter.

4.2 onCreate(): Edge-to-Edge, View Binding, Initialization

EdgeToEdge.enable() enables edge-to-edge display. ViewCompat.setOnApplyWindowInsetsListener applies system bar insets as padding. Views are bound, SensorManager obtained, and three population methods are called.

4.3 initializeViews(): RecyclerView Setup

Binds all TextView references, configures RecyclerView with LinearLayoutManager, and attaches the SensorAdapter.

4.4 populateDeviceInfo(): Device Profiling

Builds a string with manufacturer + model, Android version + API level, environment detection (emulator vs physical), and build fingerprint. Uses Build class fields and heuristic checks for emulator fingerprints.

⚠️ Watch out. Emulator detection relies on heuristic string matching of Build.FINGERPRINT, Build.MODEL, Build.HARDWARE, and Build.PRODUCT. These can vary across emulator versions and configurations. The fingerprint is included for manual verification.

4.5 populateSensorInventory(): Enumeration & RecyclerView Population

Calls sensorManager.getSensorList(Sensor.TYPE_ALL). Handles empty/null case by showing empty state. Otherwise updates the adapter and sensor count badge.

4.6 populateComparison(): MavunoLink Sensor Analysis

The core analytical method. Finds key sensors (accelerometer, gyroscope, magnetometer, light, pressure), then builds a detailed comparison focused on motion tracking for agricultural use cases. Falls back gracefully when sensors are missing.

4.7 formatSensorDetails(): Standardized Metadata Formatting

Produces a consistent multi-line string for any sensor, including all metadata fields. API 24+ fields (maxDelay, FIFO, stringType, reportingMode, wakeUp) are conditionally included.

4.8 Helper Methods: Type Names, Units, Reporting Modes

Switch-based helpers map sensor type constants to human-readable names, appropriate SI units, and reporting mode strings. Reflection handles API 28+ sensor types not available as compile-time constants.

5 · RecyclerView Adapter (SensorAdapter)

Inner static class extending RecyclerView.Adapter. Manages a list of Sensor objects, inflates item_sensor.xml, and binds data to ViewHolder. Implements expand/collapse on item click.

5.2 SensorViewHolder: View Binding & Data Population

Binds all TextView references in constructor. bind() populates summary fields, fills detail fields (with API 24+ guards), and sets up click listener for expand/collapse toggle.

💡 Tip. The adapter and ViewHolder are static to avoid implicit reference to the enclosing Activity, preventing memory leaks. Helper methods (getSensorTypeNameStatic, getUnitForSensorTypeStatic, getReportingModeNameStatic) are also static and accept Context for string resources.

10 · Key Takeaways

  • SensorManager.getSensorList(TYPE_ALL) is the single entry point for hardware sensor discovery.
  • RecyclerView + CardView provides performant, Material-styled lists with built-in view recycling.
  • Expandable item pattern (summary + hidden details container + click toggle) keeps UI clean while exposing deep metadata.
  • Build class heuristics enable emulator vs physical device detection for contextual UX.
  • API version guards (Build.VERSION.SDK_INT >= Build.VERSION_CODES.N) allow using newer Sensor APIs while maintaining minSdk 24 compatibility.
  • Domain-specific comparison logic transforms raw sensor specs into actionable engineering justification for MavunoLink's agricultural tracking requirements.
  • Static inner adapter/ViewHolder prevents memory leaks; static helper methods accept Context for resource access.
  • Material3 theming with semantic color roles (colorPrimary, colorOnSurfaceVariant, etc.) ensures consistent light/dark mode support.
